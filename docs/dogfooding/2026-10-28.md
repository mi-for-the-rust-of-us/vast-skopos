# Dogfooding `vas`, 2026-10-28 — a test rental (two RTX 3080s, rented to check `vas` itself)

Not a training rental: Éric rented two cheap boxes so that the parts of 0.3.0 and of the `next-0.4.0` branch
never seen on a real box could be seen. Claude ran `vas` (the branch's release build, with Éric's grant for
the session) and, with his agreement, uploaded two throwaway scripts to the boxes: a fake training log and two
minutes of GPU load. Times are UTC, read from the commands' output and the recorded looks.

- **Box 1:** instance 58073021, RTX 3080, Argentina, host 432420, machine 141564, $0.163/h.
- **Box 2:** instance 58073486, RTX 3080, Taiwan, host 102063, machine 35809, $0.204/h.
- **A third box,** instance 58073061, RTX 3080, Austria (host 297758, machine 143928, $0.164/h), never started. It is
  part of the findings below.

A `vas --wide --watch 10` was started before the first box was rented, so the boxes were seen from their first
second.

## Found

1. **The status message's line breaks were deleted, gluing two lines into one:** `Verifying
   Checksumc455daa85bb6:`. Fixed on the branch: a line break becomes a space (with the spaces around it), in all
   the text read from the API.
2. **`LIMIT W` matched the card on a second host.** Box 2's own machine (35809) was still listed, for another GPU
   (offer 34092774), with `LIMIT W` 370. Box 2's card read `power.limit` 370 W, default 370, `power.max_limit`
   430. So the listing's `gpu_max_power` is the card's limit, not its maximum, as on host 406325 (500 W, 10-25 and
   10-26). Neither 3080 was capped, so a lowered limit showing in a listing is still seen on one host only.
3. **A container cannot change its card's power limit.** `nvidia-smi -pl 300` answered `Insufficient
   Permissions`. A `power limit X -> Y W` line can come only from the host, so it cannot be tested from a box.
4. **Idle `power_cap`.** An RTX 3080 at 0 % and 210 MHz read `320W+power_cap`: the driver's own reason, which `vas`
   shows as it is. That is one more reason to read `+power_cap` beside the limit and the clock, never alone.

## Not seen

- **`UNREACHABLE`:** every `ssh` was answered from the boxes' first `running` look.
- **The direct-route fallback:** no proxy refused.
- **`100%?`:** the idle 3080s read 0 %, not a stuck 100 %.
- **The `<575`-style mark:** the RTX 3080 has two reference powers (320 W and 350 W) and is not in the table.
- **Note 4's question:** `vas offers --watch` was not tried during the hunt.
