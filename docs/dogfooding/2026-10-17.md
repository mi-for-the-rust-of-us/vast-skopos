# Dogfooding `vas`, 2026-10-17 — the Me36 rental (five RTX 5090s rented for three slots, askesis)

askesis's largest training run so far: ten models, two arms × five seeds, about 1 h 37 each, on three RTX 5090
boxes (chains of 4, 4 and 2 runs), 09:27 to ~18:00. Five boxes were rented to fill the three slots; `vas` watched
the whole day, read-only, beside a local readout queue.

## What worked

- **`vas offers` turned the rental from a jungle into a shortlist.** askesis's renting filters live in
  `~/.config/vast-skopos/offers` (GPU, CUDA ≥ 13, disk 50 GB, reliability ≥ 99 %, ≥ 2 days, upload ≥ 200 Mb/s,
  not mainland China, a demoted host excluded, verified); `vas offers` alone gave 20-22 offers, cheapest first.
  Éric: "what a relief".
- **`vas --ssh` told reality from the dashboard.** At ~11:00 the dashboard and the API read box 3
  `offline -> running`; one `vas --ssh` showed it training (GPU 99 %, the run's last log line), up for 79 days.
- **The money line kept the budget in sight** all day (credit $23.72 at 09:27, $12.93 at 16:40 with one box left).

## Notes for the next versions (most useful first)

1. **Offers vanish within minutes.** The list is a snapshot of a fast market. Ideas: `vas offers --watch 60` (watch
   the list move while deciding), and the time of the search in the footer. **The footer: done 2026-10-17**
   (`searched 15:42:07 UTC`); `--watch` is still open.
2. **The burn line can mislead.**
   - An instance the API reads `offline -> running` (box 3, ~11:00) was left out of "burn … over N running"
     although it may still bill. Count INTENDED running and flag the mismatch ("1 offline, billing unknown").
   - A stopped instance still bills its storage; `vas` shows no cost for it.
3. **Machine and host ids.** The `rentals.md` rows need the machine, host or datacenter id; Éric read the
   datacenter from the web UI (box 2: 406325, which the API returns as `host_id`; the others' "host id"). The API
   gives `machine_id` and `host_id`: show them (a `--wide` flag, or with `--ssh`). askesis's runbook keeps an AVOID
   list BY MACHINE (machine 142875), so `vas offers --exclude-machine` belongs beside `--exclude-host`.
   **Done 2026-10-17**: `vas --wide` shows `MACHINE` and `HOST`; `--exclude-machine` is sent as `machine_id notin`
   (probed live first: the server applies it) and re-checked on each row. **Checked on a real rental the same
   evening** (one RTX 3090, Czechia, rented to test it and destroyed after): `vas --wide` read instance 56416975 as
   machine 40935, host 135723 (the API's field names and types are the ones assumed), `vas --wide --ssh` kept the
   ids before the probe columns, and `vas offers --exclude-machine 40935` merged with the config file's filters,
   named `not machines 40935` and `searched 16:17:42 UTC` in the footer.
4. **A one-line-per-box output.** To watch the fleet the agent wrote its own ssh loop instead of
   `vas --ssh --log … --watch`: its monitor needed one line per box per tick, not a table. A `--compact` mode would
   make `vas` scriptable and fit logs and monitors.
5. **Labels.** Mapping "box 1/2/3" to instance ids caused a real mix-up in the morning (a replacement box called
   "box 3" was box 1's replacement). `vas` already shows `LABEL`, empty all day: setting a label in the dashboard at
   rental ("me36 box 1") makes every table self-explanatory. A habit, not code.
6. **`vas check` (the measured uplink) gets a sharper design.** askesis's preflight probe times ONE 50 MB upload,
   and one upload is one Hugging Face commit with a fixed cost of seconds:
   - it read Colorado at 2.48 MB/s (FAILED, launched anyway on Éric's go): its real pushes, 0.82 GB and 57 files,
     took **9 s and 15 s**;
   - it read South Korea at 5.09 MB/s (the only PASS): its real pushes took 27-32 s;
   - two US hosts moved **0 bytes** through Xet (the upload never started) while the classic path worked
     (`HF_HUB_DISABLE_XET=1`, 4.66 MB/s probe; the real push: 34 s).

   So: time TWO sizes (5 MB and 50 MB) and take the bandwidth from the slope, which cancels the commit cost, and
   probe BOTH paths (Xet and classic). A stall (0 bytes) and a crawl stay unmistakable; a fast box is no longer
   refused.
7. **A credit history.** With `--watch`, append each money line (time, credit, burn, instances running) to a small
   CSV: the rental's whole cost curve, every stop included. Éric's companion idea for askesis: the box's self-stop
   script records the account's credit (`vastai show user`) just before its final push.
