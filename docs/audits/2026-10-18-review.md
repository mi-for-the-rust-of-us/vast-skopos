# Review of the code since 0.1.0, 2026-10-18

Before 0.2.0, three fresh readers (independent agents, read-only, given the code and `CONVENTIONS.md` but
none of the author's conclusions) each read the crate through one lens. Every finding below was checked
against the code before anything was changed; each fix has a test that FAILS when the fix is reverted
(a mutation run of eleven reverted fixes: eleven caught).

The commits: `bb307de` (fixes), `513d015` (API), `6e04824` (simplifications), `e7588ad` (docs).

## Lens 1 — correctness and tests, on the code since v0.1.0

| Finding | Disposition |
|---|---|
| A config file's `--watch` fights the command line, and turns every `vas offers` into a loop | **Fixed**: `--watch` and `--changes` are refused in a config file, naming the file and line |
| A watch never gives up when its first search fails (a typo'd `VAST_URL`, a bad key); the lookout too | **Fixed**: it ends (exit 1); after one success a failure is tolerated, and the next look says `since the last successful look` |
| The table note counts new offers the table does not show (`--top 3`: "4 new", no mark) | **Fixed**: `1 new (1 below the table)` |
| Credit/burn print `-0.0`, `$-0.00`; a tiny burn prints `~inf h left` | **Fixed** (text and JSON agree: `hours_left` is `null`) |
| A duplicate offer id in one answer is marked and counted twice | **Fixed** in `select` (the row that sorts first stays) |
| `--changes` caps its lines at ten, losing ids in a log | **Fixed**: only the note under a table is capped |
| `--watch 5` is raised to 30 s without a word | **Fixed**: said once on stderr |
| The production 30 s floor is untested (every watch test lowers it) | **Tested** |
| The lookout's `--watch` has no test; one assertion (`no stamp line`) could not fail | **Tested**; the assertion is gone |
| Wiring untested: does the watch compare the full list or the rows shown? A failed search mid-watch? | **Tested** (`--top 1`; a 500 on look 2) |
| `changes()` ignores a price going `Some` to `None` | Accepted: a price that is unknown on one side cannot be said to move (documented in the test) |
| `start_date` of 1e300 gives an absurd age and cost | Accepted: not an input vast.ai sends; not worth a clamp |

## Lens 3 — simplification, clarity, I/O latency

Done (no output change): one offers table function; the cell helpers every table repeated; one ellipsis
cut; one watch loop for `vas` and `vas offers`; `probe_all` and `ssh_command` in the library, tested;
`reap()` kills and waits; one error constructor per kind in the API client; one reader for the key and
the config file; `admits` no longer rebuilds the country list per row; `with_file`'s index arithmetic.

- **Latency:** `vas --ssh` now asks for the account while the probes run, not before them. The gain is at
  most one round trip hidden behind the probes; **to be timed on a rental** (`vas --ssh`, before and
  after), not measured yet.
- **Not done:** a test that connections are reused across pages (SUSPECTED; needs a keep-alive mock),
  and `limit=100` for the instances page (the official CLI asks 25; deviating needs a probe of the API).

## What the review itself taught

- A mutation run is worth its cost: it found a test that **hung** instead of failing (a child that loops
  and keeps printing never trips a per-line timeout). The helpers now read a child's output under ONE
  deadline and wait for exit under another, so a regression fails a test instead of hanging the suite.
- Two of my own tests passed on the first run and still needed a second look: one asserted the opposite of
  its name, one could not fail. "Green" is not the same as "guarded".
