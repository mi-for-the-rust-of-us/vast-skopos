# Review of the code since 0.1.0, 2026-10-18

Before 0.2.0, three fresh readers (independent agents, read-only, given the code and `CONVENTIONS.md` but
none of the author's conclusions) each read the crate through one lens. Every finding below was checked
against the code before anything was changed; each fix has a test that FAILS when the fix is reverted
(a mutation run of eleven reverted fixes: eleven caught).

The commits: `bb307de` (fixes), `513d015` (API), `6e04824` (simplifications), `e7588ad` (docs).

## Lens 1 — correctness and tests, on the code since v0.1.0

| Finding | Disposition |
|---|---|
| A config file's `--watch` fights the command line, and turns every `vas offers` into a loop | **Fixed**: `--watch` and `--changes` are refused in a config file, naming the file and line |

| The production 30 s floor is untested (every watch test lowers it) | **Tested** |

## Lens 3 — simplification, clarity, I/O latency

Done (no output change): one offers table function; the cell helpers every table repeated; one ellipsis
cut; one watch loop for `vas` and `vas offers`; `probe_all` and `ssh_command` in the library, tested;
`reap()` kills and waits; one error constructor per kind in the API client; one reader for the key and
the config file; `admits` no longer rebuilds the country list per row; `with_file`'s index arithmetic.

- **Latency:** `vas --ssh` now asks for the account while the probes run, not before them. Timed on a
  rented RTX 5090 (155 ms away), six runs of each binary, alternating, 70 s apart (vast.ai allows ONE
  instances call per window): plain `vas`, 596 ms before and 617 ms after, no difference; `vas --ssh`,
  median 4635 ms before and 4123 ms after (mean 4758 and 4188), a gain of about half a second, which is the
  size of one account round trip, but inside a spread of 1.7 s and with the last "before" runs drifting
  slower: **consistent with the expected gain, not proof of it**. The change is kept: it is no worse and it is
  small. What dominates `vas --ssh` is the ssh handshake (about 4 s for ONE box over 155 ms); a reused
  connection (`ControlMaster`, not supported by Windows OpenSSH) would help far more than any overlap.
- **Not done:** a test that connections are reused across pages (SUSPECTED; needs a keep-alive mock),
  and `limit=100` for the instances page (the official CLI asks 25; deviating needs a probe of the API).

## What the review itself taught

- A mutation run is worth its cost: it found a test that **hung** instead of failing (a child that loops
  and keeps printing never trips a per-line timeout). The helpers now read a child's output under ONE
  deadline and wait for exit under another, so a regression fails a test instead of hanging the suite.
- Two of my own tests passed on the first run and still needed a second look: one asserted the opposite of
  its name, one could not fail. "Green" is not the same as "guarded".

# Second round: the refactor itself, 2026-10-18

The refactor of the first round (`513d015`, `6e04824`) had not been read by anyone but its author. Three
more fresh readers went over it: behaviour preservation, consistency, and tests and portability.
The commits: `23101e6` (fixes), `352545f` (tests), `4518f17` (consistency).

## Behaviour preserved? (old code against new, side by side, with reproductions)

Identical, on the inputs tried: the watch loop against the two it replaced, `with_file`'s subcommand
search (seven command lines), `admits`' country logic (padded, lower-case, NBSP, non-ASCII), the unified
offers table, `probe_all` and the `ssh` arguments, the key and config lookups, the API error texts.
One real difference, **fixed**: after the dedup of repeated ids, the footer blamed the missing rows on a
constraint ("1 dropped here: a field contradicts a constraint", with no constraint at all); it says
"1 repeated id skipped". Nits accepted: the "no credit shown" line may now come after the probes (the table
is unchanged), a thread-panic message names `host:port`, `reap` also waits.

## Consistency, staleness, docs against code

Fixed: the CHANGELOG (a one-boolean table signature written as two; a never-public `clock` listed as
narrowed; a duplicated bullet; who uses the hidden items), the comparison (0.1.0 "unreleased"), CONVENTIONS
(which flags a config file refuses; the `non_exhaustive` list), the `--help` texts (a missing
`$XDG_CONFIG_HOME`, literal backticks, askesis jargon), the `capped` doc (41, not 40), the endpoint's
trailing slash, doc links to hidden items, `docs/audits/` in the crate, a missing `// BORROW:`, the
`offers_*` argument order, and the duplications that survived the simplification (`SkoposError::ssh`,
`outcome_at`, `cut_note`). Not done: `// BORROW: explicit clone` is used three times where the rule only
names `as_str`, `as_bytes` and `to_owned` (left as a helpful extra); `Offer::machine_id` was NOT new in this
release (the reader was wrong there); the release bookkeeping (banner, version, heading) waits for the bump.

## Tests and portability (a clone, Linux through WSL, a mutation table)

Baselines green on Windows (stable, 1.88) and Linux, no flake under load. Fixed: the mock server tests broke
behind an HTTP proxy (**a loopback `VAST_URL` is never proxied**); `--ssh`, the probe's wiring, key discovery
(every place, an empty `XDG_CONFIG_HOME`, `--key-file`, UTF-16 either way), a refused account, a closed
stdout, the blank line between looks, every `-o` option, a numeric `next_token`, a flaky floor test, 435
leaked temp homes, a negative credit printing a negative runway, and **`USERPROFILE` before `HOME` on
Windows**. All fifteen survivors of the reviewer's mutation table were then killed; one of mine survived
the first time (an empty `XDG_CONFIG_HOME` is only visible through a RELATIVE path, so the test needed a
bait file in the working directory) and was strengthened.

Still open, knowingly: the `Unreadable` fallback of `ssh_probe` and the 30 s kill need a fake `ssh`
(Unix-only, `tests/remote.rs`' style); a redundant `-` host check and a redundant `burn > 0` guard cannot be
killed by any test, being equivalent; `tests/remote.rs` runs on Linux only (macOS has no `timeout`).

## What the second round taught

- The reviewers' best finds were behaviours I had introduced one fix earlier (the dedup and its footer), not
  old code: each fix deserves its own look at what it touches.
- vast.ai's API is rate-limited per endpoint and says so in `X-RateLimit-*` headers (30 per window on the
  public search, **1** on `/api/v1/instances/`): found by a latency script that got a 429. `vas` reads none of
  these headers yet; pacing a watch by them is the next piece of work.
